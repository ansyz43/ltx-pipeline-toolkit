# Квантизация и скорость: когда карта свободна, а шаг стоит 200 секунд

Разбор реального случая. Полезен тем, что симптом выглядел как нехватка памяти,
а причина была в формате весов текстового энкодера.

## Симптом

Видео-модель (MiniMax H3, 2 ветки по ~19.5 ГБ + текстовый энкодер Qwen3-VL 32B) на A100 80GB:

```
8/20  [23:24<31:11, 155.99s/it]
9/20  [26:53<38:19, 209.00s/it]
10/20 [31:08<42:27, 254.79s/it]
```

**155–255 сек/шаг** при норме порядка 45 на этом железе. Два часа на ролик.

## Ложный след: борьба за VRAM

Первая гипотеза — офлоад из-за нехватки памяти. На карте действительно сидели два
процесса ComfyUI (22 ГБ + 33 ГБ из 80). Выгрузка моделей из второго процесса
(`POST /free` с `unload_models`) память освободила — **скорость не изменилась**.

Вывод, который стоит запомнить: *совпадение «мало памяти» и «медленно» не доказывает
причинно-следственную связь.* Проверять надо замером после устранения, а не до.

## Настоящая причина — в логе загрузки модели

```
Native ops:   int8_tensorwise, convrot_w4a4
emulated ops: float8_e5m2, nvfp4, mxfp8, float8_e4m3fn
```

Стоял энкодер в формате **nvfp4_awq**. На этом GPU nvfp4 — в списке **эмулируемых**:
каждое умножение разворачивается в программную эмуляцию вместо тензорных ядер.
Отсюда и 200 сек/шаг при простаивающей карте (`utilization.gpu = 0%` при занятой VRAM —
характерный признак: память занята, вычислений нет).

Вторая строка того же лога подтверждала:

```
CLIP/text encoder model load device: cuda:0, offload device: cpu, current: cpu
```

## Решение

Замена энкодера на **int8_convrot** — формат из списка *нативных* для этой архитектуры:

| Формат энкодера | Размер | Путь исполнения |
|---|---|---|
| `nvfp4_awq` | 14.6 ГБ | эмуляция → ~200 сек/шаг |
| **`int8_convrot`** | **25.3 ГБ** | **нативные ядра** |
| `Q4_K_M` (GGUF) | 13.6 ГБ | legacy-путь, для карт с малой VRAM |

Контринтуитивно: **больший по размеру файл работает быстрее**, потому что считается
нативно. Экономия дискового места здесь прямо противоречит скорости.

## Как проверять это заранее

1. В логе загрузки найти строку `Native ops: ... emulated ops: ...` — и убедиться,
   что формат весов стоит в *native*, а не в *emulated*.
2. `nvidia-smi --query-gpu=memory.used,utilization.gpu` во время сэмплинга:
   занятая память при `utilization 0%` означает, что считает не GPU.
3. Правило под конкретное железо:
   - **A100 / Ampere** — int8_convrot нативен, nvfp4 эмулируется
   - **Blackwell** — nvfp4 нативен, можно брать компактный вариант
   - **8–12 ГБ карты** — GGUF Q3/Q4 + офлоад блоков через системную RAM

## Сопутствующее

- Глобальные флаги SageAttention на части моделей дают **чёрные кадры** (NaN) —
  включать точечно нодой в графе, а не ключом запуска.
- `--disable-dynamic-vram` лечит зависание на загрузке больших энкодеров,
  когда стейджинг кусками встаёт колом (в логе — `prepared for dynamic VRAM loading,
  NNNNN MB Staged`, после чего прогресс не двигается).
- Шаги — не единственная статья расхода: загрузка модели, кодирование текста,
  VAE-декод видео и звука не сокращаются ускорителями сэмплинга. Step-distill LoRA
  режет 20 шагов до 4, но общее время падает не в 5 раз, а меньше.
