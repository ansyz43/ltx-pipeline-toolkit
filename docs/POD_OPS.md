# Эксплуатация облачного пода под ComfyUI

Заметки по RunPod (A100 80GB / L40S), собранные на нескольких пересозданиях пода.
Применимо к любой ephemeral-GPU-аренде с сетевым томом.

## 1. Что переживает рестарт, а что нет

| Где лежит | Судьба при пересоздании пода |
|---|---|
| сетевой том (`/workspace`) | **выживает** — модели, воркфлоу, venv |
| диск контейнера (системные `site-packages`) | **стирается** — библиотеки ставить заново |

Отсюда правило: **всё ставим в `/workspace`**, а список системных зависимостей держим
скриптом, а не в голове. После каждого пересоздания отваливались `uvicorn`, `fastapi`,
`sqlalchemy`, `scipy`, `scikit-image`, `piexif`, `matplotlib`, `blend_modes`, SageAttention.

Быстрый способ закрыть почти всё разом — родной requirements самого ComfyUI, а не
выборочная доустановка по одному падению:

```bash
pip install --break-system-packages -r /workspace/ComfyUI/requirements.txt
```

## 2. Фоновый запуск: tmux не годится

На части образов `tmux` молча убивает процесс при обрыве SSH. Рабочий вариант —
отвязанный процесс плюс скрипт запуска:

```bash
setsid nohup /workspace/start_comfy.sh > /workspace/comfy.log 2>&1 < /dev/null &
```

Два правила, выведенные практикой:

- **Запуск — скриптом, а не длинной командой в SSH.** Скрипт переживает обрыв сессии
  и воспроизводится одинаково.
- **Сервер не поднялся за две минуты — читать лог, а не ждать в цикле.** Почти всегда
  там `ModuleNotFoundError` или занятый порт.

## 3. Два ComfyUI на одной карте

Зачем: основная сборка пиннится под конкретную модель (например, ComfyUI 0.28 —
выше ломается LTX-Video), а новой модели нужен свежий core. Решение — второй клон
со своим venv на другом порту.

**Модели не дублировать** — у второго экземпляра `extra_model_paths.yaml` указывает
на каталог моделей первого:

```yaml
comfyui:
    base_path: /workspace/ComfyUI/
    checkpoints: models/checkpoints
    diffusion_models: models/diffusion_models
    text_encoders: models/text_encoders
    vae: models/vae
    loras: models/loras
    upscale_models: models/upscale_models
```

**Но VRAM они делят.** Крупная видео-модель хочет карту целиком; если в соседнем
процессе висят загруженные веса, начинается офлоад. Перед тяжёлой генерацией —
выгрузить соседа:

```bash
curl -X POST http://127.0.0.1:PORT/free \
     -H 'Content-Type: application/json' \
     -d '{"unload_models":true,"free_memory":true}'
```

## 4. Мелочи, которые стоят времени

- **Jupyter занимает 8888.** Если ComfyUI планируется на этом порту — снять jupyter
  до старта, иначе порт молча занят.
- **Дисковая квота.** Том на 300 ГБ набивается быстро: один видео-стек — 40+ ГБ.
  Держать список «что можно удалить» и чистить до закачки, а не после ошибки.
- **Пустые слоты загрузки роняют граф.** Нода загрузки видео с дефолтным
  `example.mp4` кидает `FileNotFoundError`, если файла нет. Лечится файлами-заглушками
  в `input/` (генерятся ffmpeg-ом за секунду) — тогда неиспользуемый слот просто молчит:

  ```bash
  ffmpeg -f lavfi -i color=black:s=640x640:d=2:r=24 -f lavfi -i anullsrc=r=44100 \
         -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac input/example.mp4
  ```
- **`imageio-ffmpeg` для VideoHelperSuite.** Без него сборка итогового ролика падает
  в самом конце — после того, как генерация уже отработала.
- **Веб-интерфейс кеширует граф.** После правки файла воркфлоу на диске вкладку нужно
  закрыть и открыть заново из списка; простое обновление страницы показывает старую
  версию из автосохранения.
